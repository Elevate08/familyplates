## Owner decision: no invented recipe times

Direction from the project owner: a recipe must not be given a prep or cook time it doesn't state.

- `RecipeScraper`: a missing `prepTime` / `cookTime` / `totalTime` now stays `nil` (it used to default
  to 15). The OpenGraph fallback no longer sets 15/20. `total_time` falls back to the sum of whichever
  times are stated, or `nil` when there are none.
- `RecipeImportsController`: no longer fills in 15/20.
- `RecipesController#new`: the New Recipe form no longer prefills 15/20 (servings still prefills 4).
- Migration `20260914220000_remove_time_defaults_from_recipes`: drops the `recipes.prep_time` (15) and
  `recipes.cook_time` (20) column defaults. Existing rows are untouched, because a defaulted value can't be told apart from a real one.
- `CalendarFeedService`: the event description omits Prep/Cook/Servings entries that are empty
  instead of printing `Cook: m`.
- **"Quick" filter is tag-only.** `Recipe.quick` matched a quick tag *or* prep + cook ≤ 30 min, so recipes
  with no stated times (now `nil`, summed as 0) were wrongly classed as quick (found in bug review). Per owner, Quick is now
  the tag alone; the filter's search text no longer mentions "30 min". Test added.
- **Display:** an unknown time shows `—` instead of `0 mins` / `0m`. New `ApplicationHelper#recipe_minutes`
  is used on the recipe page (total, prep, cook), recipe cards and rows, planner slot and sidebar badges,
  and onboarding starter cards. `Recipe#total_time` returns `nil` rather than `0` when no time is stated.
  The slot modal's JavaScript fell back to an invented `30m`; it now shows `—`.
- Tests: scraper (no times, one stated time, OpenGraph fallback), `Recipe` (saved without times stays
  empty; `total_time` nil), `recipe_minutes` helper, and recipe show/index rendering `—`.
